# Issue #1338 — Synthetic-Data Fallback Audit (`tools/train_surrogate.py`)

> **Vertical:** `C` · **Phase:** `phase-5` · **Audit date:** 2026-06-27
> **Closes:** #1338 (depends on #1286, references #1139, #719)

## Summary

`tools/train_surrogate.py` previously fell back to a random-data generator
(`generate_synthetic_thermal_data(10000)`) whenever `data/training/` was
empty or any exception was raised while loading physics samples
(`tools/train_surrogate.py:414-415` and `tools/train_surrogate.py:600-601`).
This bypassed the #1286 fix that closed `SurrogateInputs::from_synthetic` on
the Rust side.  After this audit:

* `tools/train_surrogate.py` raises **`SystemExit` (exit code 1)** when
  `data/training/` is missing/empty and the new
  `--allow-synthetic-for-benchmark-only` flag is **not** passed.
* The CLI surfaces the benchmark-only opt-in in `--help` so CI harnesses
  retain a sanctioned way to exercise the code path.
* Every `generate_synthetic_thermal_data` callsite is annotated with the
  required `synthetic-only benchmark path — NOT for production models`
  tag, and the function's own docstring carries the full policy text.
* `data/training/README.md` documents the physics-extraction contract:
  required EnergyPlus runs, expected CSV schema, min-sample counts, and the
  canonical regenerator command.
* `tools/test_synthetic_fallback_disabled.py` (8 assertions) verifies the
  hard-error behaviour, the opt-in escape hatch, and the annotation policy.
