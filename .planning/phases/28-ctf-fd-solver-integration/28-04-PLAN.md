**Plan:** 28-04
**Status:** READY
**Effort:** 2-3 days

## Goal

Refactor the thermal model to support multiple solver backends (5R1C, CTF, FD) through a common trait-based abstraction, enabling zero-copy data sharing and clean solver switching.

**Current State:**
- `PhysicsThermalModel` has optional `ctf_solver` and `fd_solver` fields
- Solver selection is ad-hoc (if/else chains)
- Data duplication between solvers

**Target State:**
- Common `HeatConductionSolver` trait
- Unified solver interface regardless of method
- Zero-copy data sharing (shared `WallAssembly`)
- Clean solver switching via trait objects

### Task 1: Define Heat Conduction Solver Trait

**Create:** `src/physics/solver_trait.rs`

```rust
/// Common trait for all heat conduction solvers
pub trait HeatConductionSolver: Send + Sync {
    /// Get solver name/type
    fn name(&self) -> &str;

    /// Initialize solver with wall construction
    fn initialize(&mut self, wall: &WallAssembly) -> Result<(), SolverError>;

    /// Advance solver by one timestep
    ///
    /// # Arguments
    /// * `timestep` - Timestep duration [s]
    /// * `T_interior` - Interior surface temperature [°C]
    /// * `T_exterior` - Exterior surface temperature [°C]
    /// * `h_interior` - Interior convective coefficient [W/m²·K]
    /// * `h_exterior` - Exterior convective coefficient [W/m²·K]
    ///
    /// # Returns
    /// Heat flux through wall [W/m²] (positive = into zone)
    fn step(
        &mut self,
        timestep: f64,
        T_interior: f64,
        T_exterior: f64,
        h_interior: f64,
        h_exterior: f64,
    ) -> Result<f64, SolverError>;

    /// Get current energy storage rate in wall [W/m²]
    fn energy_storage_rate(&self) -> f64;

    /// Check if solver is valid (coefficients converged, etc.)
    fn is_valid(&self) -> bool;
}
```

**Verification:**
- Trait compiles
- Defines clear interface for all solvers

### Task 2: Implement Trait for 5R1C Solver

**Create:** `src/physics/five_r1c_solver.rs`

```rust
/// 5R1C thermal network solver (baseline)
pub struct FiveR1CSolver {
    /// Wall thermal resistance [m²·K/W]
    R_total: f64,
    /// Wall thermal capacitance [J/m²·K]
    C_total: f64,
    /// Interior surface resistance [m²·K/W]
    R_si: f64,
    /// Exterior surface resistance [m²·K/W]
    R_se: f64,
    /// Current heat flux [W/m²]
    q_flux: f64,
}

impl HeatConductionSolver for FiveR1CSolver {
    fn name(&self) -> &str {
        "5R1C"
    }

    fn initialize(&mut self, wall: &WallAssembly) -> Result<(), SolverError> {
        self.R_total = wall.total_resistance();
        self.C_total = wall.total_capacitance();
        self.R_si = 1.0 / wall.h_interior;
        self.R_se = 1.0 / wall.h_exterior;
        self.q_flux = 0.0;
        Ok(())
    }

    fn step(&mut self, _timestep: f64, T_int: f64, T_ext: f64, _h_int: f64, _h_ext: f64) -> Result<f64, SolverError> {
        // Standard 5R1C calculation
        self.q_flux = (T_ext - T_int) / self.R_total;
        Ok(self.q_flux)
    }

    fn energy_storage_rate(&self) -> f64 {
        // 5R1C doesn't track storage explicitly
        0.0
    }

    fn is_valid(&self) -> bool {
        self.R_total > 0.0 && self.R_total.is_finite()
    }
}
```

**Verification:**
- 5R1C implements trait correctly
- Produces same results as current implementation

### Task 3: Implement Trait for CTF Solver

**Wrap:** Existing `CTFSolver` in trait implementation

```rust
/// CTF solver wrapper
pub struct CTFSolverWrapper {
    inner: CTFSolver,
    coefficients: CTFCoefficients,
    q_flux: f64,
}

impl HeatConductionSolver for CTFSolverWrapper {
    fn name(&self) -> &str {
        "CTF"
    }

    fn initialize(&mut self, wall: &WallAssembly) -> Result<(), SolverError> {
        // Compute CTF coefficients from wall layers
        self.coefficients = CTFCalculator::compute(&wall.layers);
        self.inner = CTFSolver::new(self.coefficients.clone());
        self.q_flux = 0.0;
        Ok(())
    }

    fn step(&mut self, timestep: f64, T_int: f64, T_ext: f64, h_int: f64, h_ext: f64) -> Result<f64, SolverError> {
        // Update solver parameters
        self.inner.set_boundary_conditions(T_int, T_ext, h_int, h_ext);

        // Calculate flux
        self.q_flux = self.inner.step(timestep);
        Ok(self.q_flux)
    }

    fn energy_storage_rate(&self) -> f64 {
        // Calculate from temperature history
        self.inner.calculate_storage_rate()
    }

    fn is_valid(&self) -> bool {
        MethodSelector::validate_ctf_coefficients(&self.coefficients)
    }
}
```

### Task 4: Implement Trait for FD Solver

**Wrap:** Existing `ImplicitFDSolver` in trait implementation

```rust
/// Finite difference solver wrapper
pub struct FDSolverWrapper {
    inner: ImplicitFDSolver,
    discretization: WallDiscretization,
    q_flux: f64,
}

impl HeatConductionSolver for FDSolverWrapper {
    fn name(&self) -> &str {
        "FD"
    }

    fn initialize(&mut self, wall: &WallAssembly) -> Result<(), SolverError> {
        // Create discretization from wall layers
        self.discretization = WallDiscretization::from_layers(&wall.layers, 10);
        self.inner = ImplicitFDSolver::new(self.discretization.clone());
        self.q_flux = 0.0;
        Ok(())
    }

    fn step(&mut self, timestep: f64, T_int: f64, T_ext: f64, h_int: f64, h_ext: f64) -> Result<f64, SolverError> {
        // Create boundary conditions
        let bc_int = SurfaceBC::new_interior(h_int, T_int);
        let bc_ext = SurfaceBC::new_exterior(h_ext, T_ext);

        // Advance solver
        self.inner.step(timestep, &bc_int, &bc_ext);

        // Get surface flux
        self.q_flux = self.inner.surface_flux();
        Ok(self.q_flux)
    }

    fn energy_storage_rate(&self) -> f64 {
        // Calculate from temperature profile
        self.inner.calculate_storage_rate()
    }

    fn is_valid(&self) -> bool {
        self.inner.is_stable()
    }
}
```

**Verification:**
- FD wrapper implements trait correctly
- Produces same results as standalone FD solver

### Task 5: Refactor Thermal Model to Use Trait Objects

**Modify:** `src/sim/thermal_model.rs::PhysicsThermalModel`

**Replace:**
```rust
// OLD:
ctf_solver: Option<CTFSolver>,
fd_solver: Option<ImplicitFDSolver>,
```

**With:**
```rust
// NEW:
solvers: Vec<Box<dyn HeatConductionSolver>>,
wall_assemblies: Vec<WallAssembly>,  // Zero-copy shared data
```

**Update initialization:**
```rust
pub fn initialize_solvers(&mut self, walls: &[WallAssembly], config: &SolverConfig) {
    self.wall_assemblies = walls.to_vec();
    self.solvers = walls
        .iter()
        .map(|wall| {
            let method = self.method_selector.select_method(wall);
            match method {
                ThermalMethod::FiveR1C => {
                    Box::new(FiveR1CSolver::new()) as Box<dyn HeatConductionSolver>
                }
                ThermalMethod::CTF => {
                    Box::new(CTFSolverWrapper::new()) as Box<dyn HeatConductionSolver>
                }
                ThermalMethod::FiniteDifference => {
                    Box::new(FDSolverWrapper::new()) as Box<dyn HeatConductionSolver>
                }
            }
        })
        .collect();
}
```

    let T_zone = self.inner.temperatures[i];
    let T_outdoor = self.weather.get_temp(timestep);

        timestep_seconds,
        T_zone,
        T_outdoor,
        wall.h_interior,
        wall.h_exterior,

    zone.add_conduction_flux(q_flux * area);
}

## Notes

**Trait Design Rationale:**
- Use `Box<dyn Trait>` for runtime dispatch (needed for mixed solver types)
- Trait methods return `Result` for error handling
- `&mut self` for step method (solvers have internal state)

**Zero-Copy Strategy:**
- `WallAssembly` stored separately, referenced by solvers
- No duplication of material properties
- Coefficients cached per construction

**Performance Considerations:**
- Trait object overhead: ~10-20ns per call (negligible vs solver computation)
- Box allocation: Once during initialization, not during timestep
- Cache friendliness: Solvers stored contiguously in Vec

**Future Extensions:**
- Easy to add new solver types (e.g., frequency-domain)
- Can add solver hybridization (CTF + ML correction)
- Supports per-zone solver selection
