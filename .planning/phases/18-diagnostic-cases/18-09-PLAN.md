# Root Cause Analysis

From examining src/validation/ashrae_140_validator.rs:

The `validate_analytical_engine()` method only processes baseline cases (600-960 series) and Case 195. It does NOT process diagnostic cases (800-810) even though they are registered via `add_diagnostic_case_range()`.

The diagnostic case registration adds ranges to `self.diagnostic_cases_added` vector, but the validation loop in `validate_analytical_engine()` only iterates over hardcoded baseline cases:

```rust
let cases = if self.skip_baseline_cases {
    vec![]
} else {
    vec![
        ASHRAE140Case::Case600,
        ASHRAE140Case::Case610,
        // ... more baseline cases ...
        ASHRAE140Case::Case960,
        ASHRAE140Case::Case195,
    ]
};
```

Missing: No logic to expand diagnostic case ranges (e.g., "800-810") into actual case IDs (Case800, Case801, ..., Case810) and include them in validation.

# Existing Infrastructure

From 18-06-SUMMARY: Multi-reference database already populated with comprehensive reference ranges for all 11 HVAC equipment cases (800-810), including equipment_efficiency metrics (COP, EER) and cycling_losses.

From 18-08-PLAN (gap closure): HVAC equipment tests will be fixed to compile and execute correctly using `ThermalModel::from_spec()`.

4. Compare results against reference ranges from multi-reference DB
