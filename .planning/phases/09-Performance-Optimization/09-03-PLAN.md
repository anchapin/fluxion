**Current VectorField Operations:**

```rust
impl Add for VectorField {
    fn add(mut self, rhs: Self) -> Self {
        for (a, b) in self.data.iter_mut().zip(rhs.data.iter()) { *a += b; }
        self  // reuses self buffer
    }
}
```

- Arithmetic consumes `self` and modifies it in-place — good (no new allocation)
- `map`: creates new Vec via `iter().map().collect()` — allocates
- `zip_with`: creates new Vec via `zip().map().collect()` — allocates

**Benchmark Context:**
- `cta_bench.rs` compares raw_vec, VectorField, and ndarray map performance
- Provides baseline; improvements should show up in this benchmark

**Cache Locality Considerations:**
- Vec<f64> is AoS (array of scalars) — good for sequential access
- Ensure iterators use `iter_mut()` for write-combining
- Remove bounds checks where safe: use `get_unchecked_mut` for inner loops after length checks (only if profiler indicates bounds checks significant)
- Consider prefetch hints? Usually not needed; modern CPUs prefetch sequential well

**Potential Optimizations:**
1. `map`: Use `#[inline]` on closure parameter? Let compiler decide.
2. `zip_with`: Ensure both iterators aligned; already using `zip` — good.
3. `reduce`: Already simple fold; could use `iter().sum()` where appropriate.
4. `gradient`: Uses windows(3) which creates slices — may cause cache pressure. Optimize by manual loop.
5. Use `#[cfg_attr(debug_assertions, ...)]` to skip debug checks in release benchmarks.

**Important:** Changes must not break existing tests. Any API change should maintain trait signatures.
</context>
