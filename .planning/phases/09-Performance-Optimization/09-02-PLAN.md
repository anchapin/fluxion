Reduce heap allocations in the hot physics simulation loop by implementing reuse patterns and in-place operations.

**Purpose:** PERF-01 targets allocation reduction in `solve_timesteps`. BUG-05 addresses memory leaks/clones in hot loops. This plan identifies allocation hotspots and implements targeted optimizations without changing physics correctness.

**Output:** Modified `engine.rs` and `cta.rs` with allocation-reduced arithmetic operations. Throughput should improve or at least not regress.

**Scope:** Focus on 8760-step inner loop. Examine:
- VectorField clones in arithmetic chains
- Intermediate Vec allocations (e.g., `inter_zone_heat` as `Option<Vec<f64>>`)
- Repeated `from_scalar` and `constant_like` calls
- Redundant hashmap/vec creations in time loop
</objective>

**Key Methods:**
- `ThermalModel::solve_timesteps` (line 1923) — outer loop (8760 iterations)
- `ThermalModel::step_physics_5r1c` (line 2009) — core physics per timestep
- Inter-zone heat allocation: `Some(vec![-q_iz_total, q_iz_total])` creates Vec each call
- Multiple clones: `phi_ia.clone()`, `phi_st.clone()`, `h_ext.clone()`, etc. in arithmetic chains

**Allocation Hotspots (empirical):**
1. `inter_zone_heat` Vec allocation for multi-zone (8760× allocations)
2. `VectorField::constant_like` creating new Vec each call
3. Cloning vectors in arithmetic: `num_tm.clone() + num_phi_st.clone() + num_rest_with_iz.clone()`
4. `as_ref().to_vec()` conversions for reductions

**Optimization Strategy:**
- Use `take_replace` or `mem_replace` for in-place updates where feasible
- Add `add_assign`, `mul_assign` to ContinuousTensor trait (implement for VectorField)
- Pre-allocate reusable buffers (e.g., `inter_zone_heat` as reusable array on ThermalModel)
- Eliminate `Option<Vec<f64>>` by returning small array or in-place modification
- Move `daily_cycle` array out of per-timestep allocation (already constant)
</context>
