# Plan 24-07: 5R1C vs 6R2C Side-by-Side Comparison

**Type:** `auto`
**Wave:** 3 — Integration Tracing
**Depends on:** 24-06 (heat flow tracing instrumentation)

---

## Goal

Create automated comparison tests that run identical cases with both 5R1C and 6R2C, comparing all internal states and outputs. Build confidence that differences (or lack thereof) are understood.

---

## Tasks

### 1. Create Comparison Test Framework

**What:** Build infrastructure for running paired 5R1C/6R2C simulations.

**Actions:**
- Create `tests/5r1c_vs_6r2c_comparison.rs` (new dedicated file)
- Add comparison runner:
  ```rust
  pub struct ComparisonRunner {
      pub case_config: CaseConfig,
      pub weather: WeatherData,
      pub result_5r1c: SimulationResult,
      pub result_6r2c: SimulationResult,
  }

  impl ComparisonRunner {
      pub fn run_both(&mut self) -> ComparisonResult;
      pub fn compare_states(&self) -> StateComparison;
      pub fn compare_energy(&self) -> EnergyComparison;
  }
  ```
- Add comparison metrics:
  - Mean absolute error (MAE) for temperatures
  - Root mean square error (RMSE) for heat flows
  - Annual energy difference (%)
  - Peak load difference (%)
  - Time lag correlation (does one lead the other?)

**Deliverable:** Comparison test framework

---

### 2. Compare Case 600 (Low-Mass Baseline)

**What:** Verify 5R1C and 6R2C agree for low-mass buildings.

**Actions:**
- Run Case 600 with both models
- Compare:
  - Annual heating energy (both should be ~5.5-7.5 MWh)
  - Annual cooling energy (both should be ~8.0-10.5 MWh)
  - Peak heating load (both should be ~2.0-3.0 kW)
  - Peak cooling load (both should be ~3.0-4.0 kW)
  - Hourly indoor temperature (MAE < 0.5°C expected)
- Expectation: Should agree closely (both within ASHRAE 140 tolerance)
- If they disagree: **bug in one or both models**

**Deliverable:** Case 600 comparison report

---

### 3. Compare Case 900 (High-Mass Problem)

**What:** Compare models for the problematic high-mass case.

**Actions:**
- Run Case 900 with both models
- Compare same metrics as Case 600
- Expectation based on prior results:
  - Both should give ~5.35 MWh heating (262-322% high)
  - Both should give ~4.75 MWh cooling (29-123% high)
  - Internal states may differ, but outputs same
- Key question: **Do internal states differ even though outputs match?**
  - If yes: 6R2C has different physics but same output (structural limitation)
  - If no: 6R2C is identical to 5R1C (implementation bug)

**Deliverable:** Case 900 comparison report

---

### 4. Compare All ASHRAE 140 Cases

**What:** Systematic comparison across all 18 cases.

**Actions:**
- Run all cases (600, 610, 620, 650, 900, 910, 920, 950, etc.)
- For each case, compare:
  - Annual heating (%)
  - Annual cooling (%)
  - Peak heating (%)
  - Peak cooling (%)
- Create summary table:
  | Case | Mass Level | ΔHeating | ΔCooling | ΔPeak Heat | ΔPeak Cool |
  |------|------------|----------|----------|------------|------------|
  | 600  | Low        | +0.5%    | +0.3%    | +0.1%      | +0.2%      |
  | 900  | High       | +0.0%    | +0.0%    | +0.0%      | +0.0%      |
- Identify patterns:
  - Do models diverge more for high-mass?
  - Do models diverge more for cooling vs heating?
  - Any cases where 6R2C is significantly different?

**Deliverable:** Comprehensive comparison table

---

### 5. Compare Internal State Time-Series

**What:** Detailed comparison of temperatures and heat flows over time.

**Actions:**
- For Case 900, plot time-series (sample week in winter, week in summer):
  - T_mass (6R2C) vs T_effective (5R1C)
  - T_surface (6R2C) vs T_surface (5R1C)
  - Q_HVAC (6R2C) vs Q_HVAC (5R1C)
  - Q_solar absorbed (6R2C) vs Q_solar absorbed (5R1C)
- Calculate statistics:
  - Mean difference
  - Standard deviation
  - Maximum difference
  - Time lag (cross-correlation analysis)
- Identify when differences are largest:
  - During heating season?
  - During cooling season?
  - During sunny vs cloudy periods?
  - During occupied vs unoccupied hours?

**Deliverable:** Time-series comparison plots + statistics

---

### 6. Test Extreme Mass Scenarios

**What:** Push models to extremes to reveal differences.

**Actions:**
- Create synthetic cases:
  - **Infinite mass:** C_m → ∞ (temperature should be constant)
  - **Zero mass:** C_m → 0 (should reduce to steady-state)
  - **Massive floor only:** All mass in floor, none in walls
  - **Massive walls only:** All mass in walls, none in floor
- Run both models for each extreme case
- Compare responses:
  - Do both handle infinite mass correctly?
  - Do both reduce to steady-state with zero mass?
  - Do both respond correctly to mass distribution changes?
- Expectation: Both should handle extremes correctly (if not, **bug**)

**Deliverable:** Extreme mass scenario comparison

---

### 7. Test Timestep Sensitivity Comparison

**What:** Compare how models respond to timestep changes.

**Actions:**
- Run Case 900 with both models at varying timesteps:
  - Δt = 1 hour, 30 min, 15 min, 6 min, 1 min
- Compare convergence:
  - Does 5R1C converge faster (fewer nodes)?
  - Does 6R2C converge slower (more nodes, more coupling)?
  - Do both converge to same answer as Δt → 0?
- If they converge to different answers:
  - **Major finding:** Structural difference, not numerical
- If they converge to same answer:
  - Both have same fundamental limitation

**Deliverable:** Timestep sensitivity comparison

---

### 8. Document Comparison Results

**What:** Create comprehensive comparison report.

**Actions:**
- Write `docs/5R1C_VS_6R2C_COMPARISON.md` with:
  - Methodology (comparison framework)
  - Case 600 results (low-mass baseline)
  - Case 900 results (high-mass problem)
  - All 18 cases summary table
  - Time-series analysis (key plots)
  - Extreme scenario results
  - Timestep sensitivity results
  - **Conclusion:** Why does 6R2C show no improvement?
    - Implementation bug (identical due to error)
    - Structural limitation (different physics, same output)
    - Numerical issue (timestep too coarse)

**Deliverable:** Comprehensive comparison report
