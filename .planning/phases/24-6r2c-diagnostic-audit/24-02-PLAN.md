# Plan 24-02: 6R2C Code-to-Spec Conformance Audit

**Type:** `auto`
**Wave:** 1 — Specification Audit
**Depends on:** 24-01 (ISO 13790 specification document)

---

## Goal

Audit the existing 6R2C implementation against the ISO 13790 specification verified in Plan 24-01. Identify any discrepancies between spec and code.

---

## Tasks

### 1. Map Specification to Code Locations

**What:** Create a traceability matrix linking each equation to implementation.

**Actions:**
- Read `docs/ISO_13790_6R2C_SPECIFICATION.md` (from 24-01)
- Search codebase for 6R2C implementation:
  - `src/sim/thermal_model.rs` — main thermal network
  - `src/sim/engine.rs` — timestep integration
  - `src/physics/` — conductance calculations
  - `tests/test_6r2c_thermal_mass.rs` — existing tests
- Create traceability table: Spec Equation → Code Location → Line Numbers

**Deliverable:** Traceability matrix (Markdown table)

---

### 2. Audit Conductance Calculations

**What:** Verify each conductance calculation matches specification.

**Actions:**
- For each conductance (h_tr_em, h_tr_ms, h_tr_wm, h_tr_is, h_tr_es):
  - Extract code implementation
  - Compare formula against spec
  - Check unit conversions
  - Verify constant values (density, specific heat, surface coefficients)
- Flag any discrepancies

**Deliverable:** Conductance audit report with pass/fail for each

---

### 3. Audit Capacitance Calculations

**What:** Verify thermal mass capacitance calculations.

**Actions:**
- Check `C_m` calculation (internal mass):
  - Which materials are included?
  - Effective mass fraction applied correctly?
  - Volume → mass → capacitance conversion correct?
- Check `C_s` calculation (surface mass, if applicable):
  - Same verification as C_m
- Compare against Case 900 expected values

**Deliverable:** Capacitance audit report

---

### 4. Audit Heat Balance Implementation

**What:** Verify the differential equations are implemented correctly.

**Actions:**
- Extract surface node heat balance from code
- Extract mass node heat balance from code
- Compare against spec equations term-by-term
- Check:
  - Sign conventions (gain/loss)
  - Coupling terms between nodes
  - Solar gain distribution (which node receives solar?)
  - Internal gain distribution (convective vs radiative split)
  - Ventilation heat loss term

**Deliverable:** Heat balance audit report

---

### 5. Audit Timestep Integration

**What:** Verify numerical integration method.

**Actions:**
- Identify integration method (explicit Euler, implicit, Crank-Nicolson?)
- Check stability criteria for chosen method
- Verify timestep application (1 hour = 3600 seconds?)
- Check initial conditions for capacitance nodes
- Verify boundary condition application at each timestep

**Deliverable:** Integration audit report

---

### 6. Document Discrepancies

**What:** Create comprehensive discrepancy report.

**Actions:**
- List all discrepancies found (spec vs code)
- Categorize by severity:
  - **Critical:** Wrong formula, would cause accuracy issues
  - **Major:** Missing term, incomplete implementation
  - **Minor:** Unit conversion inconsistency, code style
- For each discrepancy:
  - Describe the issue
  - Show spec vs code comparison
  - Estimate impact on accuracy
  - Recommend fix

**Deliverable:** `docs/6R2C_CODE_AUDIT_DISCREPANCIES.md`

---

## Verification Criteria

**Plan succeeds when:**
1. ✅ Traceability matrix complete (all spec equations mapped to code)
2. ✅ Conductance audit complete (all 6 conductances verified)
3. ✅ Capacitance audit complete (both nodes verified)
4. ✅ Heat balance audit complete (both equations verified)
5. ✅ Integration audit complete (timestep method verified)
6. ✅ Discrepancy report created (or confirmed no discrepancies)

---

## Expected Output

- **Document:** `docs/6R2C_CODE_AUDIT_DISCREPANCIES.md` (or `6R2C_CODE_AUDIT_PASSED.md` if clean)
- **Artifact:** Traceability matrix
- **Tests:** None (audit only, fixes in subsequent plans)

---

## Notes

- If critical discrepancies found, pause and report immediately
- This audit may reveal multiple root causes — document all of them
- Be thorough: even "obviously correct" code should be verified against spec
