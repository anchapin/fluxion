### 2. Root Cause Tree Analysis

**What:** Create fault tree to trace root cause(s) systematically.

**Actions:**
- Start with top-level problem: "Case 900 annual heating 262-322% high"
- Build fault tree:
  ```
  Top Event: Annual heating energy 262-322% high

  Branch 1: Implementation Bug
  ├─ Conductance calculation error? (verified by 24-03)
  ├─ Node placement error? (verified by 24-04)
  ├─ Heat balance equation error? (verified by 24-02)
  └─ Integration error? (verified by 24-05)

  Branch 2: Numerical Issue
  ├─ Timestep too coarse? (verified by 24-05)
  ├─ Integration method unstable? (verified by 24-05)
  └─ Convergence failure? (verified by 24-07)

  Branch 3: Structural Limitation
  ├─ RC network topology insufficient? (verified by 24-07, 24-09)
  ├─ Missing thermal lag mechanism? (verified by 24-09)
  └─ Cannot capture multi-layer dynamics? (verified by 24-09)

  └─ Natural convection not modeled? (out of scope)
  ```
- For each leaf node, mark as:
  - ✅ Verified correct (not a cause)
  - ❌ Verified incorrect (root cause found)
  - ⚠️ Partially correct (contributing factor)

**Deliverable:** Root cause fault tree diagram

### 3. Confidence Assessment

**What:** Assess confidence level for each finding.

**Actions:**
- For each finding, assess:
  - **Evidence strength:** How directly was this tested?
    - Direct test (unit test, comparison) = High confidence
    - Indirect test (integration test) = Medium confidence
    - Analysis only (no test) = Low confidence
  - **Reproducibility:** Can the finding be reproduced?
    - Reproduced multiple times = High confidence
    - Reproduced once = Medium confidence
    - Not reproduced = Low confidence
  - **Alternative explanations:** Are there other possible causes?
    - No alternatives = High confidence
    - 1-2 alternatives = Medium confidence
    - Many alternatives = Low confidence
- Combine into overall confidence score (High/Medium/Low)

**Deliverable:** Confidence assessment table

---

### 4. Quantify Impact of Each Root Cause

**What:** Estimate how much each root cause contributes to the error.

**Actions:**
- For each confirmed root cause, estimate impact:
  - **Timestep coarseness:** If Δt=1hr→6min reduces error from 300% to 200%, impact = 100%
  - **RC structural limitation:** If CTF gets 1.5 MWh vs RC 5.35 MWh, impact = 3.5 MWh
  - **Implementation bug:** If fixing bug changes result by X MWh, impact = X MWh
- Create Pareto chart:
  - X-axis: Root causes (timestep, structure, bugs, etc.)
  - Y-axis: Contribution to error (MWh or %)
  - Shows which causes dominate
- Identify "vital few" vs "trivial many":
  - 20% of causes typically account for 80% of error

**Deliverable:** Impact quantification (Pareto chart data)

### 5. Evaluate Fix Options

**What:** For each root cause, evaluate potential fixes.

**Actions:**
- Create evaluation table:
  | Root Cause | Fix Option | Effort | Expected Impact | Risk | Recommendation |
  |------------|------------|--------|-----------------|------|----------------|
  | Timestep coarse | Sub-stepping (6×10min) | Low | Reduce error 20-30% | Low | ✅ Implement |
  | RC structure | Adopt CTF method | High | Reduce error 80-90% | Medium | ⚠️ Consider for v1.0 |
  | RC structure | Hybrid RC+ML | Medium | Reduce error 50-70% | Low | ✅ Consider for v0.6 |
  | Node placement | Recalculate positions | Low | Unknown | Low | ⚠️ If bug found |
- For each fix, estimate:
  - **Effort:** Lines of code, weeks of work
  - **Expected impact:** Error reduction (%)
  - **Risk:** Likelihood of breaking existing functionality
  - **Performance impact:** Throughput change (%)

**Deliverable:** Fix options evaluation table

---

### 6: Formulate Go/No-Go Recommendation

**What:** Data-driven recommendation on RC network approach.

**Actions:**
- Define decision criteria:
  - **Go (continue with RC):**
    - Root cause is fixable bug (not structural)
    - Fix effort < 2 weeks
    - Expected to achieve ±15% accuracy
    - Performance impact < 50%
  - **No-Go (pivot to alternative):**
    - Root cause is structural limitation
    - Fix effort > 4 weeks
    - Expected accuracy still > ±15%
    - Performance impact > 50%
  - **Conditional Go (hybrid approach):**
    - Keep RC for low-mass buildings
    - Adopt alternative for high-mass buildings
    - Implement ML correction factor
- Make recommendation based on findings:
  - If implementation bugs found: **Go** (fix bugs)
  - If timestep issue only: **Conditional Go** (sub-stepping)
  - If structural limitation: **No-Go** (pivot to CTF/finite difference/ML)

**Deliverable:** Go/No-Go recommendation with justification
