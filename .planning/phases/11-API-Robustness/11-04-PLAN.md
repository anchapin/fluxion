  <action>Add predict_loads_with_fallback() method to SurrogateManager:

1. Add new method:
   - pub fn predict_loads_with_fallback(&self, temps: &[f64]) -> Result<Vec<f64>, FluxionError>
   - Returns Result with successful loads or FluxionError::Surrogate

2. Implementation pattern:
   - Try ONNX first: match self.predict_loads_batched(&[temps.to_vec()])
   - If Ok(loads): return loads.pop().unwrap()
   - If Err(e):
     * Log warning: log::warn!("ONNX inference failed: {}, falling back to analytical mode", e)
     * Fallback to analytical: self.analytical_loads(temps)
     * If analytical succeeds: return loads
     * If analytical fails: return FluxionError::Surrogate("ONNX and analytical fallback both failed: {e}")

3. Create analytical_loads() helper method:
   - fn analytical_loads(&self, temps: &[f64]) -> Result<Vec<f64>, String>
   - Implement analytical load calculation (similar to ThermalModel use_ai=false path)
   - Use existing analytical formulas for solar radiation, infiltration, convection
   - Return Result with loads or error message

4. Document the fallback behavior in doc comments:
   - Explain ONNX tried first, analytical fallback used on failure
   - Note that fallback is logged with warnings
   - Clarify that simulation continues with reduced accuracy but increased reliability

Pattern from 11-RESEARCH.md: Wrap ONNX inference with fallback to analytical; log warnings; return specific error if both fail
