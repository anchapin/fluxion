# Gap Context (from VERIFICATION.md):
Plan 07-01 explicitly stated key link: "sensitivity.rs → BatchOracle via evaluate_population". However, the current implementation in src/analysis/sensitivity.rs creates ThermalModel directly and uses rayon::par_iter() for parallel evaluation, bypassing BatchOracle's session pooling and GPU batching optimizations. This is an architectural deviation.

# Current Implementation (problematic):
- run_sensitivity likely:
  1. Builds design matrix (Vec<Vec<f64>>)
  2. Iterates with rayon::par_iter()
  3. For each parameter set: creates ThermalModel, applies parameters, runs solve_timesteps
  4. Collects results

# Required Refactor:
- Option A: Accept BatchOracle as argument to run_sensitivity, call oracle.evaluate_population(design_matrix, use_surrogates)
- Option B: Refactor run_sensitivity to internally construct and use BatchOracle
- Must maintain backward compatibility or update call sites (likely CLI command in src/bin/fluxion.rs)

# Considerations:
- BatchOracle::evaluate_population expects population: Vec<Vec<f64>> and returns Vec<f64> (fitness scores, typically EUI)
- Sensitivity analysis may need to run with surrogates enabled or disabled; BatchOracle supports use_surrogates flag
- Need to ensure thermal model parameters in the population vector match BatchOracle's expected gene semantics (params[0]=window_u_value, params[1]=hvac_setpoint, etc.)
- The design matrix should include all parameters that the BatchOracle expects (gene vector length consistent with model)

# Implementation Steps:
1. Read src/analysis/sensitivity.rs to understand current structure
2. Identify how parameters are mapped to ThermalModel (apply_parameters expects certain parameters)
3. Refactor evaluation loop: construct population matrix, call BatchOracle.evaluate_population(params, use_surrogates)
4. Update any call sites (likely in CLI command for sensitivity) to pass BatchOracle or use_surrogates flag
5. Ensure tests still pass (unit tests in sensitivity.rs should work with either approach)
6. Benchmark that sensitivity still produces correct metrics

# After refactor:
- cargo test sensitivity should pass
- cargo test --test-threads=1 to verify no race conditions
- Manual check: fluxion sensitivity command still works and produces CSV output
