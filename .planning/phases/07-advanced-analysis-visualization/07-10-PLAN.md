# Gap Context (from VERIFICATION.md):
The `update_references` command implementation appears correct (uses reqwest::blocking::Client), but unit tests fail with HTTP 501 Not Implemented from mockito. The test setup uses global `mockito::mock` which may not match the actual request path. The fix is to rewrite tests using `mockito::Server` instance to control URL and ensure path matching.

# Existing Implementation:
- src/validation/commands.rs contains `update_references` function that fetches JSON from a URL
- Tests are in the same file (mod tests) and in tests/validation/multi_reference_integration.rs
- The integration test `test_update_references_with_remote` fails with 501

# Root Cause:
Mockito's global mock may be set up with a path pattern that doesn't match the actual request URL. Using a `mockito::Server` instance provides better control over the mock endpoint URL.

# Solution Approach:
1. Replace `mockito::mock("GET", "/")` with `mockito::Server::new()` and `server.mock("GET", "/path")`
2. Adjust the request URL in the test to point to the server's URL (e.g., `server.url()`)
3. Ensure the mock path matches exactly what update_references requests (likely "/" or "/refs.json" depending on URL)
4. Verify mock returns valid JSON and correct status (200)
5. Keep the test logic otherwise the same

# Files to modify:
- src/validation/commands.rs (test module): Rewrite test_update_references_success and test_update_references_upgrade
- tests/validation/multi_reference_integration.rs: Rewrite test_update_references_with_remote

# After changes:
- Run `cargo test update_references` to verify unit tests pass
- Run `cargo test multi_reference_integration` to verify integration test passes
