```
### Pitfall 7: Wiring Validation Too Broad or Too Narrow
**What goes wrong:** Validation checks everything (too slow) or nothing (misses bugs)
**Why it happens:** Static analysis is too broad; runtime tracing needs careful scope
**How to avoid:** Focus on critical integration points: `solve_timesteps()` → `predict_loads()`, `BatchOracle::evaluate_population()` → `ThermalModel::apply_parameters()`. Use feature flags to enable/disable.
```

**Key insight:** Research recommends runtime tracing (not static analysis) focused on critical integration points.

  <name>Task 1: Decide on automated dependency checking approach</name>
  <decision>Should we implement automated dependency checking (static analysis) or accept manual runtime tracing as sufficient for INTEG-08?</decision>
  <context>
  INTEG-08 expected "Wiring validation system automatically checks module dependencies and integration points", but only manual runtime tracing (WiringTracer) exists.

  **Current implementation:**
  - WiringTracer provides manual runtime tracing (tests call record_call() manually)
  - No automated static analysis of module imports/exports
  - No automated dependency graph validation

  **Research recommendation:**
  - Runtime tracing (not static analysis) is preferred for wiring validation
  - Focus on critical integration points: solve_timesteps → predict_loads
  - Manual tracing is acceptable if it catches real wiring issues

  **INTEG-08 requirement interpretation:**
  - "Automatically checks" could mean: (a) automated static analysis at compile time, OR (b) automated runtime tracing during test execution
  - Current approach: (b) automated runtime tracing - tests automatically verify calls if WiringTracer is integrated
  - Gap: WiringTracer is not integrated into ThermalModel (manual recording required)

  **Options:**
  1. Implement automated static analysis (build custom dependency graph checker, integrate into CI)
  2. Accept runtime tracing as sufficient (integrate WiringTracer into ThermalModel for automatic call recording)
  3. Hybrid approach (runtime tracing + optional static analysis for specific checks)

  **Tradeoffs:**
  - Option 1: True "automated checking" at compile time, but complex to build and maintain
  - Option 2: Simpler, aligns with research recommendation, runtime tracing catches actual wiring issues
  - Option 3: Balanced, but adds complexity
  </context>
  <options>
    <option id="option-1-static-analysis">
      <name>Implement automated static analysis</name>
      <pros>
        - True "automated checking" at compile time (catches issues before tests run)
        - Validates module imports/exports, dependency graph structure
        - Runs fast as part of cargo check/clippy
        - Integrates well into CI/CD pipeline
      </pros>
      <cons>
        - Complex to build (custom dependency graph analysis, integration with cargo)
        - May generate false positives (modules imported but not used for specific reasons)
        - Requires maintenance as codebase evolves
        - Research recommends runtime tracing, not static analysis
      </cons>
    </option>
    <option id="option-2-runtime-tracing-integrated">
      <name>Integrate WiringTracer into ThermalModel for automatic call recording</name>
      <pros>
        - Simpler implementation (add tracer field to ThermalModel, record calls in solve_timesteps)
        - Aligns with research recommendation (runtime tracing)
        - Catches actual wiring issues during test execution
        - Plan 21-06 already addresses WiringTracer integration in tests
      </pros>
      <cons>
        - Runtime-only (doesn't catch issues at compile time)
        - Requires tests to enable tracing (can't be in production code)
        - Manual integration into ThermalModel (new field, call recording points)
      </cons>
    </option>
    <option id="option-3-accept-current-approach">
      <name>Accept manual runtime tracing as sufficient for INTEG-08</name>
      <pros>
        - Minimal code changes (document rationale, update VERIFICATION.md)
        - Plan 21-06 will enhance tests to use WiringTracer for verification
        - Research recommends runtime tracing focused on critical integration points
        - No additional complexity or maintenance burden
      </pros>
      <cons>
        - Doesn't provide "automated checking" in the strictest sense
        - Manual recording in tests (not automatic call tracking)
        - May not satisfy strict interpretation of INTEG-08
      </cons>
    </option>
  </options>
  <resume-signal>Select: option-1-static-analysis, option-2-runtime-tracing-integrated, or option-3-accept-current-approach</resume-signal>
