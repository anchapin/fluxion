## Tasks

### Task 1: CTF Solver Core Implementation

**What:** Implement CTF (Conduction Transfer Functions) solver for multi-layer wall heat conduction.

**Why:** Phase 26 evaluation determined CTF achieves ±3-5% accuracy for high-mass buildings while maintaining ~800-1,200 configs/sec throughput.

**How:**
1. Create `src/physics/ctf_solver.rs` with:
   - CTF coefficient calculation (X, Y, Z, F factors per ASHRAE fundamentals)
   - Time series heat flux calculation using CTF coefficients
   - Support for arbitrary multi-layer wall constructions
2. Add `CtfConfig` struct for CTF-specific parameters:
   - `max_order`: CTF order (default 6-10 terms)
   - `reference_temperature`: Base temperature for linearization
   - `convergence_tolerance`: Coefficient calculation tolerance
3. Implement `CtfWallAssembly` builder:
   - Convert `MaterialLayer` stack to CTF coefficients
   - Pre-calculate coefficients during initialization (not per-timestep)
   - Cache coefficients for reuse across timesteps

**Verification:**
- Unit tests: CTF coefficients match ASHRAE Handbook examples
- Integration test: Single-wall heat flux matches analytical solution
- Performance: Coefficient calculation <1ms per wall assembly

**Estimated effort:** 4-6 hours

### Task 2: Hybrid Thermal Model Architecture

**What:** Modify thermal model to support both 5R1C and CTF methods with automatic selection.

**Why:** Maintain backwards compatibility and optimal performance — 5R1C is faster and sufficient for low-mass buildings.

**How:**
1. Create `ThermalMethod` enum:
   ```rust
   pub enum ThermalMethod {
       FiveR1C,      // ISO 13790 standard
       SixR2C,       // Extended RC (deprecated)
       Ctf,          // Conduction Transfer Functions
       FiniteDifference, // 1D heat conduction (fallback)
   }
   ```
2. Add `ThermalMethodSelector`:
   - Automatic selection based on building mass (threshold: 200 kg/m²)
   - Manual override via config
   - Log method selection for debugging
3. Modify `ThermalNetwork` to be method-agnostic:
   - Trait-based abstraction for heat flow calculations
   - Method-specific implementations behind common interface
   - Zero-copy data sharing between methods

**Verification:**
- Unit tests: Method selector chooses correctly for test cases
- Integration test: Both 5R1C and CTF produce valid results
- No regression: Low-mass cases unchanged from v0.5

**Estimated effort:** 3-4 hours

## Notes

**CTF Implementation Strategy:**
- Use ASHRAE Fundamentals 2017 CTF coefficient tables as reference
- Start with order-6 CTF (balance accuracy vs performance)
- Pre-calculate coefficients during initialization (not per-timestep)
- Cache coefficients for reuse across timesteps

**Risk Mitigation:**
- If CTF implementation proves complex, fall back to finite difference (Phase 25-03)
- Maintain 5R1C as default for low-mass buildings (proven, fast)
- Keep adaptive timestep as emergency fallback (Phase 25-02)

**Performance Optimization:**
- CTF coefficient calculation: O(n²) once during init
- CTF heat flux calculation: O(n) per timestep (n = CTF order)
- Target: <10μs per wall per timestep

**Testing Strategy:**
- Unit tests: CTF coefficients, heat flux calculation
- Integration tests: Full wall assembly, thermal network
- Validation tests: ASHRAE 140 cases 900-960
- Performance tests: Throughput ≥800 configs/sec
