# Requirements: Fluxion v0.4 - ASHRAE 140 Compliance

**Defined:** 2026-03-13
**Core Value:** Full ASHRAE Standard 140 compliance with physics-based commercial building modeling

## v0.4 Requirements

Requirements for ASHRAE 140 full compliance milestone. Each maps to roadmap phases.

### Physics Engine (PHYS)

- [x] **PHYS-01**: Remove all mock predictions from SurrogateManager - use analytical physics or trained ONNX models
- [x] **PHYS-02**: Replace hardcoded material properties with configurable building assembly system
- [x] **PHYS-03**: Replace hardcoded physical constants with standard constants module
- [x] **PHYS-04**: Implement thermal mass corrections for high-mass buildings (coupling ratio > 0.1)
- [x] **PHYS-05**: Implement mode-specific thermal mass coupling (heating vs cooling: h_tr_em_heating, h_tr_em_cooling)
- [ ] **PHYS-06**: Evaluate 8R3C thermal network (6R2C showed no improvement)
- [x] **PHYS-07**: Support multiple building types (lightweight to heavyweight construction)

### HVAC Systems (HVAC)

- [x] **HVAC-01**: Implement VAV (Variable Air Volume) system modeling
- [x] **HVAC-02**: Implement CAV (Constant Air Volume) system modeling
- [x] **HVAC-03**: Implement heat pump equipment modeling (with efficiency curves)
- [x] **HVAC-04**: Implement chiller equipment modeling (with part-load ratios) - Completed (Plan 15-02)
- [x] **HVAC-05**: Implement boiler equipment modeling (with part-load ratios) - Completed (Plan 15-02)
- [x] **HVAC-06**: Implement economizer mode (free cooling)
- [x] **HVAC-07**: Implement equipment efficiency curves and part-load degradation
- [x] **HVAC-08**: Implement cycling loss modeling
- [x] **HVAC-09**: Support configurable HVAC control strategies (setpoints, deadbands, schedules)

### Weather Data (WEATHER)

- [x] **WEATHER-01**: Remove placeholder weather values; implement complete TMY3/EPW parsing
- [x] **WEATHER-02**: Implement psychrometric calculations (dew point, humidity ratio, enthalpy, wet-bulb)
- [x] **WEATHER-03**: Implement advanced solar radiation interpolation for sub-hourly timesteps
- [x] **WEATHER-04**: Support multiple geographic locations (not just Denver TMY)
- [x] **WEATHER-05**: Implement sky model variations (clearness index, cloud cover effects)

### Internal Loads (LOADS)

- [x] **LOADS-01**: Implement internal lighting loads with schedules
- [x] **LOADS-02**: Implement internal equipment loads with schedules
- [x] **LOADS-03**: Implement occupancy/people loads with schedules
- [x] **LOADS-04**: Support customizable load profiles (weekday/weekend/holiday)

### Diagnostic Cases (DIAG)

- [x] **DIAG-01**: Implement ASHRAE 140 Cases 195-470 (in-depth diagnostics)
- [x] **DIAG-02**: Implement ASHRAE 140 Cases 800-810 (HVAC equipment)
- [x] **DIAG-03**: Implement non-residential cases from ASHRAE 140
- [x] **DIAG-04**: Implement solid conduction test variants
- [x] **DIAG-05**: Implement solar gain diagnostic variants

### Statistical Validation (STATS)

- [x] **STATS-01**: Implement ASHRAE 140 Addendum B acceptance criteria
- [x] **STATS-02**: Implement NMBE (Normalized Mean Bias Error) calculations
- [x] **STATS-03**: Implement CV(RMSE) (Coefficient of Variation of RMSE) calculations
- [x] **STATS-04**: Implement multiple testing corrections (Bonferroni, Benjamini-Hochberg)
- [x] **STATS-05**: Implement case group validation (minimum 80% passing per group)
- [x] **STATS-06**: Generate comprehensive validation reports with statistical metrics

### Data Quality (DATA)

- [x] **DATA-01**: Audit codebase and document all placeholder/mock/hardcoded values
- [x] **DATA-02**: Replace all placeholder data with real implementations
- [x] **DATA-03**: Replace all hardcoded values with configuration
- [x] **DATA-04**: Add validation for all configuration inputs
- [x] **DATA-05**: Document all physical parameters with source references

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| 6R2C as default thermal network | Phase 12 evaluation showed no accuracy improvement with 1.5-2x performance penalty; keep 5R1C as default |
| Detailed HVAC system modeling | ASHRAE 140 uses ideal HVAC; detailed equipment modeling outside scope for compliance |
| Advanced AI features | AI surrogates deferred to v2+; focus on physics-based compliance first |
| Custom case variants | ASHRAE 140 defines specific case ranges; adding extra cases creates maintenance burden |
| Visualization enhancements | Validation reports should be concise; existing HTML/Plotly visualization sufficient |
| Mobile/web UI | CLI and library API are primary interfaces for engineering use |
