## Executive Summary

**v0.6 Achievement:** 75% improvement in high-mass accuracy (from 229-322% error down to ±30-50% error) through:
- 5R1C thermal mass correction
- Sky temperature model (Walton with dewpoint)
- View factors for roof/wall surfaces
- Half-node boundary formulation

**v0.7 Goal:** Complete high-mass accuracy work by integrating advanced solver (CTF or finite difference) to achieve **±15% annual energy tolerance** for all ASHRAE 140 cases.

**Success Criteria:**
1. ✅ Case 900 annual heating: 1.17-2.04 MWh (currently ~2.29 MWh, 31% low)
2. ✅ Case 900 annual cooling: 2.13-3.67 MWh (currently within range)
3. ✅ All 18 ASHRAE 140 cases within ±15% tolerance
4. ✅ Performance ≥800 configs/sec throughput
5. ✅ CTF or FD solver integrated and production-ready

## Technical Approach

### Solver Selection Strategy

**Primary:** CTF (Conduction Transfer Functions)
- ±3-5% accuracy for high-mass buildings (Phase 26 evaluation)
- ~800-1,200 configs/sec throughput
- EnergyPlus-proven method (20+ years)
- Precomputed coefficients (efficient runtime)

**Fallback:** Finite Difference
- ±3-5% accuracy for high-mass buildings
- ~500-800 configs/sec throughput
- More robust for extreme constructions
- Simpler math (no Laplace transforms)

**Default:** 5R1C (unchanged for low-mass)
- Maintain ±15% accuracy for 600/800-series
- ~2,575 configs/sec throughput
- ISO 13790 compliant

### Method Selection Threshold

**Thermal Mass Threshold:** τ > 2 hours (time constant)

**Calculation:**
```rust
tau = (mass_thickness * density * specific_heat) / U_value
```

**Selection Logic:**
```rust
if tau > 2.0 hours {
    use_ctf_or_fd()  // High-mass
} else {
    use_5r1c()  // Low-mass
}
```

### Integration Architecture

**Trait-based Abstraction:**
```rust
pub trait ThermalSolver {
    fn calculate_heat_flux(&mut self, t_interior: f64, t_exterior: f64, dt: f64) -> f64;
    fn update_state(&mut self, flux: f64);
    fn get_method(&self) -> ThermalMethod;
}

pub struct FiveR1CSolver { ... }
pub struct CTFSolver { ... }
pub struct FiniteDifferenceSolver { ... }
```

**Zero-Copy Data Sharing:**
- Solvers share common `WallAssembly` data structure
- Precomputed coefficients cached per construction
- No allocation during timestep loop

## Risk Management

### Technical Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| CTF integration too complex | Medium | High | Use FD solver as fallback; both achieve ±3-5% |
| Performance below target | Low | Medium | Optimize coefficient caching; reduce CTF order |
| Regression on low-mass | Low | High | Extensive 600/800-series testing; method selector gating |
| Extreme construction edge cases | Medium | Low | FD fallback for constructions CTF can't handle |

### Schedule Risks

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|------------|
| Phase 28 takes longer than expected | Medium | Medium | Parallel development (CTF + FD teams) |
| Validation reveals issues | Medium | High | Buffer time in Phase 29; iterative tuning |
| Documentation backlog | Low | Low | Start docs early; integrate with code |

## Out of Scope

Explicitly excluded from v0.7. Documented to prevent scope creep.

- **Moisture modeling** — Deferred to v1.0 or v2.0
- **Natural ventilation** — Deferred to v1.0
- **Advanced HVAC systems** (VRF, radiant, DOAS) — Deferred to v1.0
- **ML surrogate models** — Deferred to v1.0 (research track)
- **GPU acceleration** — Deferred to v1.0 (optimization track)
- **Multi-building district modeling** — Deferred to v2.0
