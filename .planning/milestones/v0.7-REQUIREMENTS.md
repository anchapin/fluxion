# Requirements: v0.7 Thermal Physics Complete

**Defined:** 2026-03-17
**Milestone:** v0.7 Thermal Physics Complete
**Previous:** v0.6 Validation Excellence (shipped 2026-03-17)
**Goal:** Complete high-mass accuracy work with CTF/FD solver integration

---

## Context

**v0.6 Achievement:** 75% improvement in high-mass accuracy
- Case 900 heating: from 229-322% error down to ~31% error (2.29 MWh vs 1.17-2.04 MWh reference)
- Implemented: thermal mass correction, sky temperature model, view factors, half-node formulation
- CTF/FD solvers implemented but experimental (not integrated)

**v0.7 Goal:** Complete the high-mass accuracy work
- Target: ±15% annual energy tolerance for all ASHRAE 140 cases
- Method: Integrate CTF or finite difference solver into production thermal model
- Success: Case 900 heating 1.17-2.04 MWh, cooling 2.13-3.67 MWh

---

## Solver Integration Requirements (SOLVER)

### Core Integration

- [x] **SOLVER-01**: CTF solver integrated into main thermal model
  - `src/physics/ctf_solver.rs` integrated with `ThermalModel`
  - CTF coefficients precomputed during initialization
  - Runtime heat flux calculation using CTF coefficients
  - Unit tests: coefficient calculation, heat flux accuracy
  - **Status:** ✅ COMPLETE - Integrated in Phase 28

- [x] **SOLVER-02**: Finite difference solver integrated as fallback option
  - `src/physics/finite_difference.rs` integrated with `ThermalModel`
  - Implicit BTCS scheme for stability
  - Configurable spatial discretization (nodes per layer)
  - Unit tests: convergence, stability, energy conservation
  - **Status:** ✅ COMPLETE - Integrated in Phase 28

- [x] **SOLVER-03**: Automatic method selection based on building characteristics
  - `ThermalMethodSelector` struct with selection logic
  - Threshold-based selection (thermal mass time constant τ)
  - Manual override via config for testing/debugging
  - Logging of method selection for debugging
  - **Status:** ✅ COMPLETE - Auto selection implemented

- [x] **SOLVER-04**: Method selection threshold configuration
  - Default threshold: τ > 2 hours → CTF/FD
  - Configurable via Python API and CLI
  - Documentation of threshold selection rationale
  - Sensitivity analysis on threshold value

- [x] **SOLVER-05**: Zero-copy data sharing between solver methods
  - Common `WallAssembly` data structure
  - Shared material layer properties
  - Cached coefficients per construction
  - No allocation during timestep loop

- [x] **SOLVER-06**: Solver configuration via Python API and CLI
  - Python: `ModelConfig.solver_method = "ctf" | "fd" | "auto"`
  - CLI: `--solver-method ctf|fd|auto`
  - Configuration validation and error messages
  - Documentation of all solver options

## Out of Scope

Explicitly excluded from v0.7. Deferred to future milestones.

### Deferred to v1.0

- **Moisture modeling** — Hygrothermal coupling
- **Natural ventilation** — Advanced infiltration models
- **Advanced HVAC systems** — VRF, radiant, DOAS
- **ML surrogate models** — Neural network emulators
- **GPU acceleration** — CUDA/OpenCL implementation

### Deferred to v2.0

- **Multi-building district modeling** — Urban scale simulation
- **Co-simulation** — FMI/FMU integration
- **Optimization algorithms** — Built-in parametric runs
- **Uncertainty quantification** — Monte Carlo, polynomial chaos
