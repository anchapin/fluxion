# Fluxion Delivery Pipeline

The workflow context for how issues become merged PRs in fluxion: the wave pipeline,
its CI gate lanes, and the rules that keep wall-clock speed from eroding validation
trust. (Planning artifact; lives in `.planning/` because `check_root_hygiene.py`
blocks new root-level `.md` files.)

## Language

**Wave**:
A batch of up to 3 GitHub issues worked in parallel, one branch/PR each, pushed and created simultaneously.
_Avoid_: batch, sprint, run

**Cycle time**:
Wall-clock hours from PR creation to merge (measured median ~3 h, range 1–5 h, Sep 2026).
_Avoid_: lead time, turnaround

**Fast lane**:
The per-PR required checks that empirically catch real defects: Workspace, Rustfmt, Clippy, Energy Conservation, 3× cycle guards, Docs Hygiene, Known-Issues-Stale, Architecture Drift, Module Size, Cargo Deny, Audit Freshness, MSRV, Tracked-vs-Ignored, Crate Size, FFI. Critical path ~20–27 min (rust-tests.yml is the pole).
_Avoid_: quick checks, smoke lane

**Path-filtered gate**:
A required check that runs only when its trigger paths change (established pattern: Surrogate Drift Gate on `**/surrogate*.rs`). Lane 2 = ASHRAE blind validation + isolation suites, Strict Energy #1333, h_tr_em, Fast-Math ← **physics path class** (`src/**`, `fluxion-core/**`, `fluxion-fluid/**`, `tests/**`, `models/**`, `weather/**`); binding gates ← binding paths. Strict Energy and h_tr_em stay per-PR deliberately (crown jewels under RULES.md) despite zero recent failures.
_Avoid_: conditional check, partial gate

**Nightly authority**:
A slow, near-zero-recent-failure gate that runs nightly on `develop` instead of blocking each PR; verdict binding via the merge freeze. Lane 3 (ratified 2026-09-15): Determinism matrix #1351, perf gates #1618/#2693/#2772/#2919/#2922, Code Coverage #1932, CUDA Smoke #1603; mutation/fuzz already nightly.
_Avoid_: optional check, deferred gate

**Merge freeze**:
The rule that no Wave merges (and no new Wave starts) while the latest nightly authority run on `develop` is red. One exception: the **freeze-breaker** — a single diagnostic agent that gets the failing check log + the develop merges since last green nightly, and consumes the morning's milestone slot. Qualifies as "stuck" for user notification.
_Avoid_: lockdown, code freeze

**Blind window**:
The maximum time a merged defect can hide before an authoritative gate sees it. Rejected Tier-3 proposal: 7 days. Chosen design: ≤ ~18 h (one nightly cycle).

**Progress telegram**:
A weekly comment on the pinned v1.3 Progress Tracker issue (β-soak-tracker pattern): scorecard pass-rate delta, milestone-vs-hygiene merge mix, lane cycle-time p50s, fix-loop rate, cancelled-run share, LIMIT-gap count. Generated by `scripts/progress_telegram.py`.
_Avoid_: status report, dashboard

**Wave-mix rule**:
Every Wave reserves ≥ 1 of its ≤ 3 slots for a milestone-moving issue.
_Avoid_: quota, slot rule

**Milestone-moving issue**:
An issue whose resolution changes engine behavior or the ASHRAE 140 validation posture (Phase B–E work, LIMIT-gap closures, solver regressions like #3770). Carries the `milestone` label so wave-planner can enforce the wave-mix rule; supply is created by Phase decomposition (PM), not by gap-issues audits.
_Avoid_: feature work, big issue

**Hygiene issue**:
An issue resolving CI/docs/tooling/deps debt that does not change engine behavior (≈ 60 % of recent merges; default filler for the Wave's remaining slots).

**Overflow fleet**:
Self-hosted runners carrying the `[self-hosted,fluxion-overflow]` label that absorb jobs beyond GitHub-hosted concurrency (Free plan: 20; Pro: 40). This dev machine is a 2-slot member; fork-PR isolation is mandatory on public repos.
_Avoid_: self-hosted pool (ambiguous), Hetzner (historical name)

**Pre-push ladder**:
The proportional local checks every implementation sub-agent runs before pushing (fmt + clippy + `ci-local.sh` always; scoped module tests on code; scoped ASHRAE suites on physics path class; ratchet-file protocol on test/ignore changes). Canonical text lives in `docs/agents/pre-push-checklist.md`.
_Avoid_: pre-flight (overloaded), local CI

**Fix-push etiquette**:
When a CI check fails: reproduce locally, batch all known fixes into ONE push. Never push per-check — unbatched pushes trigger ADR-0015 cancel-storms (15 wasted runs observed per 250).

## Relationships (pipeline mechanics)

- Every implementation sub-agent climbs the **pre-push ladder**; every CI sub-agent follows **fix-push etiquette**
- A red **nightly-authority** run freezes **Waves** until green — the **blind window** never exceeds one nightly cycle

## Relationships

- A **Wave** contains up to 3 issues → up to 3 PRs, and includes ≥ 1 **milestone-moving issue** (wave-mix rule)
- Every PR passes all **fast-lane** gates; **path-filtered gates** apply per path class; **nightly-authority** gates bind via the **merge freeze**, not branch protection
- **Cycle time** is bounded below by the fast-lane critical path (~25 min), not by nightly-authority gates
- A red **nightly-authority** run freezes **Waves** until green — the **blind window** never exceeds one nightly cycle

## Example dialogue

> **Dev:** "If the determinism matrix isn't a required check anymore, what stops a cross-platform break from merging?"
> **Owner:** "Nothing stops it *merging* — that's the blind window, ≤ 18 h. The nightly run catches it, the merge freeze stops the next morning's waves, and the fix becomes that morning's milestone-moving slot."

> **Dev:** "Can I fill a wave with three deps bumps to drain the backlog faster?"
> **Owner:** "No — wave-mix rule. One milestone-moving issue rides in every wave; hygiene fills the rest."

## Flagged ambiguities

- "Progress" was used to mean both *merge throughput* and *milestone movement* (scorecard pass rate) — resolved: progress = milestone movement; throughput is only a means. Hence the wave-mix rule.
- "Turn off checks for a week" (Tier 3 / gate holiday) was proposed and **rejected** on 2026-09-15: gates that fail are fast ones already kept per-PR; slow ones rarely fire; reconciliation across ~100 merges is a bisection problem (see #3770 for the cost of one escaped regression).
- "Required" in GitHub branch-protection cannot express nightly checks — resolved: nightly authority is enforced by the wave orchestrator (merge freeze), with `release_gates.yaml` retaining the canonical classification.
