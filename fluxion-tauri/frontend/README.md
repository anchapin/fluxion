# Fluxion GUI Frontend

React + React Three Fiber frontend for the Fluxion Tauri desktop app and
standalone web mode. Loads building geometry through two interchangeable
paths that share one R3F canvas:

- **BEM** — the `load_geometry` Tauri IPC wire contract (web fallback: an
  embedded mirror of the Rust sample building), triangulated and shaded with
  the GLSL thermal shader (`src/scene/ThermalMaterial.tsx`).
- **glTF** (issue #3175) — a committed sample glTF 2.0 building model
  (`src/assets/sample-building.gltf`, <1 MB, regenerated by
  `npm run gltf:sample`) parsed with the GLTFLoader shipped in `three`.
  Meshes named `Zone_{id}` (suffixed forms like `Zone_2_Roof` map to the
  same zone) are joined against the LiveTwin `zone_states` stream and
  colored by zone temperature; meshes without a `Zone_{id}` name render
  neutral gray, and live zones that own no mesh surface as legend/console
  warnings — never a crash.

## Commands

```bash
npm install        # first time in a fresh checkout/worktree
npm run dev        # Vite dev server (web mode)
npm test           # vitest — pure-logic suites incl. zone→mesh mapping
npm run build      # tsc -b && vite build (must pass clean)
npm run gltf:sample # regenerate src/assets/sample-building.gltf
```

The committed glTF asset is pinned to the programmatic builder by
`tests/gltfAsset.test.ts` (the same sync-pin pattern as the embedded BEM
sample). If you edit `src/gltf/buildSampleGltf.ts`, run `npm run gltf:sample`
and commit the regenerated asset together with the builder change.

## Manual render verification (macOS & Linux)

The automated suites cover the pure mapping/color logic and a real
GLTFLoader round-trip in Node; visual rendering is verified manually on
both platforms (WebGL output is not asserted headlessly):

1. `npm install && npm run dev`, open the printed URL
   (Chrome/Chromium or Firefox; macOS additionally Safari 16+).
2. Confirm the BEM sample renders (surfaces, orbit by dragging, zoom with
   the wheel, "Reset View" restores framing).
3. Click **glTF** in the control bar — the box-y sample building
   (zones + dark roof slab + gray ground pad) loads in place of the BEM
   surfaces. The status bar reads `Geometry: glTF sample (Zone_{id} meshes)`.
4. Zone coloring: `Zone_1/2/3` boxes show distinct palette colors matching
   the sidebar legend; the `Site_Pad` slab is neutral gray.
5. Start a LiveTwin stream (or **WASM Sim** as fallback), enable
   **Thermal**: zone boxes shade through the 5-stop blue→red colormap per
   live `t_air`; the pad stays neutral. The legend shows min/max labels.
6. Expected warnings (by design): the legend lists `Site_Pad` as an
   unmatched mesh; a stream carrying a zone id ≥ 4 also lists that zone as
   mesh-less. DevTools console carries the same via `console.warn`.
7. Repeat on the other OS. Linux: use X11 or WebGL-capable Wayland
   (EGL); a software rasterizer (`LIBGL_ALWAYS_SOFTWARE=1`) is acceptable
   for functional checks.
8. `npm run build` must pass clean on both platforms.
