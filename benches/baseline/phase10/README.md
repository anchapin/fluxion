# Phase 10 Performance Baselines

This directory contains performance baseline data for Phase 10 quality testing.

## Baseline Establishment

Baselines are established using Criterion's baseline functionality. The key benchmarks tracked:

1. **Thermal Model Solve Performance** (`thermal_model_solve_*zones`)
   - 1, 10, 50, 100 zone configurations
   - 1-year simulation (8760 timesteps)
   - Pure physics performance (no AI surrogates)

2. **BatchOracle Throughput** (`batch_oracle_*`)
   - Population sizes: 100, 1,000, 10,000 configurations
   - Analytical mode (physics-only)
   - Surrogate mode (with AI predictions)
   - Measured in configs/second throughput

3. **VectorField Operations** (`vectorfield_*`)
   - Addition, subtraction, multiplication, division
   - Vector sizes: 10, 100, 1,000 elements
   - CTA operation performance validation

## Usage

### Run all benchmarks with baseline comparison
```bash
cargo bench --bench performance_regression -- --baseline phase10
```

### Run specific benchmark group
```bash
cargo bench --bench performance_regression thermal_model -- --baseline phase10
```

### Update baselines
```bash
cargo bench --bench performance_regression -- --save-baseline phase10
```

### Variance Testing

Run 10 iterations to verify variance <5%:
```bash
for i in {1..10}; do
  echo "Run $i/10..."
  cargo bench --bench performance_regression -- --baseline phase10 > /tmp/bench_$i.log 2>&1
done
```

### Analyze Variance

Check Criterion output for variance percentages:
- All benchmarks should show <5% variance
- Document any benchmarks exceeding threshold

## Baseline Files

Baselines are stored in `target/criterion/{benchmark_name}/phase10/`:

- `benchmark.json`: Benchmark configuration
- `estimates.json`: Statistical estimates (mean, std dev)
- `sample.json`: Sample data points
- `tukey.json`: Tukey HSD test results

These files are generated by Criterion and used for regression detection.

## Regression Detection

Criterion will automatically compare current performance against baseline:

- **No change**: Performance within expected variance
- **Performance improved**: Faster than baseline
- **Performance regressed**: Slower than baseline (>5% threshold)

CI integration (Task 3) will gate PRs with regressions >5%.

## Notes

- Baselines are machine-specific; re-establish when running on different hardware
- Use release builds for consistent measurements
- Sample size reduced to 10 for faster iteration; increase to 100 for production baselines
- Full benchmark suite takes ~10-15 minutes on 8-core CPU
