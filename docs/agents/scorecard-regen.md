# Scorecard regeneration coupling (issue #3128)

`SCORECARD.md` is generated by `scripts/generate_scorecard.py` from three committed sources — `docs/ASHRAE140_RESULTS.md`, `release_gates.yaml`, and `README.md` — so changing any source requires regenerating the scorecard.
The `Scorecard Drift Gate` workflow enforces this with `python3 scripts/generate_scorecard.py --check`, which fails the build on drift.
On `pull_request` events the workflow now auto-regenerates and pushes the result back to your PR branch when drift is detected (job `Scorecard Drift Gate (Issue #2496)`); manual regen is still supported via `python3 scripts/generate_scorecard.py`.
On `push` to `develop`/`main` the workflow does NOT auto-commit (protected branches must land via PR review) — drift there fails the gate so an operator can fix it manually.

## What to do as an agent

- Edit any of the three sources — the next PR run of `scorecard-drift` will auto-regenerate and push.
- If you need the regenerated file locally (e.g. to cite figures in a downstream PR), run `python3 scripts/generate_scorecard.py` before committing.
- If the gate fails on a `push` event to `develop`/`main`, open a PR that touches `SCORECARD.md` directly; the auto-regen path only fires on `pull_request`.
