# Issue #719 Epic Plan: v2.1 Synthetic Training Data Generation

## Executive Summary

This plan details the synthetic training data generation pipeline for Phase 4 surrogate model training. The pipeline will generate diverse, physics-based training data covering the zone thermal solver (6R2C network), solar gain calculations, and identified computational bottlenecks.

**Prerequisite**: Phase 1 (v1.3) must achieve ≥80% ASHRAE 140 blind validation pass rate before v2.1 training data is used for production surrogate models.

---

## 1. Background & Scope

### 1.1 Current State

From `ARCHITECTURE.md`:
- **Module Status**: Zone Balance (Partial), Conduction (Yes), Ventilation (Yes), Solar (Yes)
- **Trait Hierarchy**: `HeatConductionSolver` → 5R1C/CTF/FD, `VentilationSchedule`, `ThermalModelTrait`
- **SurrogateInputs** (from `src/ai/surrogate.rs:146-153`):
  ```rust
  pub struct SurrogateInputs {
      pub exterior_temp: f64,    // °C
      pub zone_temp: f64,       // °C
      pub solar_rad: f64,       // W/m²
      pub humidity: f64,         // %
      pub occupancy: f64,       // dimensionless
      pub climate_zone: String,  // ASHRAE climate zone
  }
  ```

### 1.2 Target Surrogate Components

| Component | Physics Module | Input Features | Output Targets |
|-----------|---------------|----------------|----------------|
| Zone Thermal Solver | `ThermalModelTrait` | T_ext, T_zone, Q_solar, Q_vent, Q_int | T_zone_next, Q_HVAC |
| Solar Gain | `sim/solar.rs` | lat, lon, time, DNI, DHI, surface orientation | Beam, diffuse, ground_reflected gains |
| Conduction | `HeatConductionSolver` | T_int, T_ext, wall_properties | Heat flux [W/m²] |

### 1.3 Identified Bottlenecks

1. **Zone temperature prediction** - 6R2C thermal network is computationally expensive for annual simulations
2. **Solar irradiance distribution** - Per-surface calculations for multi-zone models
3. **HVAC interaction loops** - Zone temperature → HVAC demand → load → temperature feedback

## 2. Synthetic Data Schema

### 2.1 Zone Thermal Solver Dataset

```python
@dataclass
class ZoneThermalRecord:
    # Identifier
    scenario_id: str
    timestep: int

    # Input features (match SurrogateInputs)
    exterior_temp: float      # °C
    zone_temp: float          # °C
    solar_rad: float          # W/m²
    humidity: float           # %
    occupancy: float          # fraction 0-1
    climate_zone: str          # "4A", "5A", etc.

    # Additional context
    hour_of_day: int          # 0-23
    day_of_year: int         # 1-365
    hvac_mode: str            # "heating", "cooling", "off"

    # Building characteristics
    zone_area_m2: float
    zone_volume_m3: float
    window_ratio: float       # fraction
    wall_U_value: float      # W/m²K
    thermal_mass_MJ_K: float

    # Physics outputs (training targets)
    zone_temp_next: float     # °C - next timestep zone temp
    hvac_power: float         # W - heating (+) / cooling (-)
    energy_storage: float     # W - thermal mass charge/discharge
```

### 2.2 Solar Gain Dataset

```python
@dataclass
class SolarGainRecord:

    # Surface properties

    surface_area: float      # m²

    # Output targets
    beam_gain: float         # W
    diffuse_gain: float     # W
    ground_reflected_gain: float  # W
    total_gain: float       # W
    sol_air_temp: float     # °C
```

### 2.3 Conduction Dataset

```python
@dataclass
class ConductionRecord:
```

#### Task A.3: Weather Profile Generator

**Location**: `scripts/generate_training_data.py`

Generate realistic weather sequences using:
- TMY3 data statistics (mean, std, autocorrelation)
- Extreme value distributions for design conditions
- Smooth transitions for transient weather events

**Profile Types**:
1. **Temperate** - 5-25°C, low day-to-day variability
2. **Continental** - -10-35°C, high seasonal swing
3. **Tropical** - 20-35°C, monsoon patterns
4. **Desert** - 10-45°C, extreme diurnal swing
5. **Coastal** - 10-30°C, marine moderation

### 4.2 Phase B: Zone Thermal Data Generation (Week 2-3)

#### Task B.1: Zone Thermal Simulation Runner

**Location**: `scripts/generate_training_data.py`

**Process**:
1. For each scenario:
   - Initialize `PhysicsThermalModel` with building parameters
   - Run 1-year simulation at hourly timesteps
   - Record `ZoneThermalRecord` every timestep
2. Parallel execution across CPU cores

**Output Format**: Parquet with compression
```
data/synthetic/v2.1/zone_thermal/
├── train.parquet
├── val.parquet
├── test.parquet
└── metadata.json
```

#### Task B.2: Target Computation

For each record, compute:
- `zone_temp_next`: T_zone at t+1h (training target)
- `hvac_power`: Estimated HVAC demand to maintain setpoint
- `energy_storage`: C_mass × (T_mass - T_zone)

### 4.3 Phase C: Solar Gain Data Generation (Week 3)

### 4.5 Phase E: Quality Assurance (Week 4)

#### Task E.1: Data Validation

```python
def validate_dataset(dataset: Dataset) -> ValidationResult:
    """Validate synthetic dataset quality."""
    issues = []

    # Check for NaN/Inf
    for col in dataset.numeric_columns:
        if dataset[col].isna().any():
            issues.append(f"NaN found in {col}")
        if not np.isfinite(dataset[col]).all():
            issues.append(f"Non-finite values in {col}")

    # Check target distribution
    targets = dataset['zone_temp_next']
    if targets.std() < 0.5:
        issues.append("Target distribution too narrow")

    # Check feature coverage
    for feature, (min_val, max_val) in EXPECTED_RANGES.items():
        actual_min = dataset[feature].min()
        actual_max = dataset[feature].max()
        if actual_min < min_val or actual_max > max_val:
            issues.append(f"{feature} out of expected range")

    return ValidationResult(issues)
```

#### Task E.2: Physics Consistency Checks

1. **Energy balance**: Q_cond + Q_solar + Q_vent + Q_int + Q_HVAC ≈ 0
2. **Temperature monotonicity**: T_zone_next ≈ T_zone when all loads zero
3. **HVAC sign consistency**: heating when T_zone < setpoint, cooling when T_zone > setpoint

## 6. Integration with Surrogate Training

### 6.1 Expected Model Architecture

From `src/ai/surrogate.rs`:
- Input: 6 features (exterior_temp, zone_temp, solar_rad, humidity, occupancy, climate_zone)
- Output: 2 targets (zone_temp_next, hvac_power) or scalar for single-target models

**Recommended Architecture** (from `docs/adaptive_timestep/ML_TRAINING_DATA_GENERATION.md`):
```rust
pub struct ThermalSurrogateModel {
    layers: vec![
        Linear(6, 128),   // input -> hidden
        Linear(128, 128),  // hidden -> hidden
        Linear(128, 64),   // hidden -> hidden
        Linear(64, 2),     // hidden -> output
    ],
    activation: LeakyReLU(0.1),
    dropout: 0.1,
}
```

### 6.2 Training Pipeline

1. Load Parquet datasets
2. Apply normalization (save params for inference)
3. Train with early stopping on validation loss
4. Evaluate on held-out test set
5. Export to ONNX format for inference in Fluxion
