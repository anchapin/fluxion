# Test Writing Guide for Fluxion

> **TL;DR**: Practical guidance for writing tests in the fluxion building energy modeling codebase.
> **Key decisions**: Descriptive names | Reference data CSVs | approx!() tolerances | Edge case coverage
> **Owned by**: QA / Physics Team
> **Reviewed**: 2026-07-13

## Overview

Fluxion tests follow a **module isolation-first** strategy per ARCHITECTURE.md. Each physics module (Weather, Solar, Conduction, Ventilation, Zone Balance) must pass isolated tests before system-level ASHRAE 140 tests are run.

## Test Naming Convention

Use descriptive, self-documenting names that specify:
- The function/method being tested
- The input conditions
- The expected behavior or reference

### Good Examples

```rust
// Solar position at specific location/date
#[test]
fn solar_altitude_40N_summer_solstice_matches_epplus() { ... }

// Steady-state heat flux
#[test]
fn five_r1c_steady_state_q_equals_deltat_over_r() { ... }

// Edge case: zero conductance
#[test]
fn ventilation_ach_returns_zero_for_calm_wind_no_stack() { ... }

// ASHRAE 140 case
#[test]
fn case_900_annual_heating_within_ashrae_140_range() { ... }
```

### Pattern: `{module}_{condition}_{expected}_matches_{reference}`

| Component | Example |
|-----------|---------|
| Module prefix | `solar_`, `conduction_`, `ventilation_`, `zone_balance_` |
| Condition | `40N_summer_solstice`, `steady_state`, `extreme_wind` |
| Expected | `altitude_azimuth_zenith`, `q_equals_deltat_over_r` |
| Reference | `epplus`, `ashrae_handbook`, `analytical` |

## Reference Data Usage

Reference data CSVs live in `tests/reference_data/`. Use them for **EnergyPlus parity tests**.

### Loading Reference Data

```rust
use std::fs;
use std::path::Path;

fn load_reference_data() -> Vec<ReferenceRow> {
    let path = Path::new("tests/reference_data/solar/surface_irradiance_south.csv");
    let content = fs::read_to_string(path)
        .unwrap_or_else(|e| panic!("Failed to read {:?}: {}", path, e));

    let mut rows = Vec::with_capacity(8760);
    for line in content.lines() {
        let trimmed = line.trim();
        if trimmed.is_empty() || trimmed.starts_with('#') {
            continue;
        }
        let parts: Vec<&str> = trimmed.split(',').collect();
        if parts[0].contains("hour") {
            continue; // Skip header
        }
        rows.push(ReferenceRow { ... });
    }
    rows
}
```

### Reference Data CSV Format

Each CSV should have:
- Header row with column names
- Comment lines starting with `#`
- Data rows with consistent column ordering
- 8760 hourly rows for full-year data

```
# Surface irradiance on south-facing wall - Denver TMY3
# Generated by EnergyPlus 25.2.0
hour,beam_irradiance,ground_diffuse_irradiance
1,0.0,12.3
2,0.0,11.8
...
```

## Physics Tests with `approx!()`

Use the `approx` crate for floating-point comparisons with explicit tolerances.

### Tolerance Standards

| Quantity | Tolerance | Rationale |
|----------|-----------|-----------|
| Energy (kWh, MWh) | 1% | Small % error compounds over 8760 hours |
| Temperature (°C) | 0.5°C | 1% of typical 50°C ΔT range |
| Heat flux (W/m²) | 1% | Energy flux density |
| Solar angle (°) | 0.5° | NOAA approximation ceiling |
| ACH | 0.05 ACH | 10% of 0.5 ACH default |
| Conductance (W/K) | 1% | Physical conductance |

### Using `assert_relative_eq!`

```rust
use approx::{assert_relative_eq, assert_relative_eq_arr};

#[test]
fn solar_position_summer_solstice_denver() {
    let pos = calculate_solar_position(39.74, -105.18, 2024, 6, 21, 12.0, None);

    // Within 0.5° for angles
    assert_relative_eq!(
        pos.altitude_deg, 72.3,
        epsilon = 0.5,
        max_relative = 0.01
    );

    assert_relative_eq!(
        pos.azimuth_deg, 180.2,
        epsilon = 0.6,
        max_relative = 0.01
    );
}

#[test]
fn annual_beam_energy_within_1_percent() {
    let total_beam = compute_annual_beam_energy();
    let reference = 1847.3; // kWh/m²-year

    assert_relative_eq!(
        total_beam, reference,
        epsilon = 0.01,
        max_relative = 0.01  // 1% = 18.47 kWh
    );
}
```

### Array Comparisons

```rust
#[test]
fn hourly_temperatures_match_reference() {
    let hours: Vec<f64> = (0..8760)
        .map(|h| model.get_temperature(h))
        .collect();

    for (i, (got, expected)) in hours.iter().zip(reference).enumerate() {
        assert_relative_eq!(
            got, expected,
            epsilon = 0.5,
            max_relative = 0.01,
            "Hour {}: got {:.2}°C, expected {:.2}°C", i, got, expected
        );
    }
}
```

## Edge Cases to Test

Every physics module should have edge case coverage:

### NaN and Inf

```rust
#[test]
fn solar_position_handles_invalid_inputs() {
    // Extreme altitude (should clamp)
    let pos = calculate_solar_position(100.0, 0.0, 2024, 6, 21, 12.0, None);
    assert!(pos.altitude_deg.is_finite());

    // Negative values
    let pos = calculate_solar_position(-90.0, 0.0, 2024, 6, 21, 12.0, None);
    assert!(pos.altitude_deg.is_finite());
}
```

### Zero and Negative Values

```rust
#[test]
fn ventilation_ach_non_negative() {
    let vent = ConstantVentilation::new(0.0);
    assert!(vent.get_ach(0, 20.0, 24.0, 0.0, 0.0) >= 0.0);

    // Negative outdoor temp
    assert!(vent.get_ach(0, 20.0, -10.0, 0.0, 100.0) >= 0.0);
}

#[test]
fn conduction_flux_zero_when_no_temperature_difference() {
    let solver = FiveR1CSolver::new(&wall_spec);
    let flux = solver.step(T_int, T_ext, T_int, dt); // ΔT = 0
    assert!((flux - 0.0).abs() < 1e-10);
}
```

### Extreme Values

```rust
#[test]
fn extreme_window_u_values() {
    // MIN_U_VALUE = 0.1
    let flux = solver.step(20.0, -30.0, 0.1, 3600.0);
    assert!(flux.is_finite());

    // MAX_U_VALUE = 5.0
    let flux = solver.step(20.0, -30.0, 5.0, 3600.0);
    assert!(flux.is_finite());
}

#[test]
fn thermal_model_handles_extreme_outdoor_temps() {
    let mut model = ThermalModel::new(1);

    // Extreme cold
    model.step_physics(0, -40.0, 3600.0);
    assert!(model.temperatures[0].is_finite());

    // Extreme heat
    model.step_physics(0, 50.0, 3600.0);
    assert!(model.temperatures[0].is_finite());
}
```

### Timestep Boundaries

```rust
#[test]
fn timestep_boundary_conditions() {
    let dt = 3600.0; // 1 hour

    // Step at dt=0 (should not crash)
    let flux = solver.step(T_int, T_ext, 0.0);

    // Very small timestep
    let flux = solver.step(T_int, T_ext, 1e-6);

    // Very large timestep (annual)
    let flux = solver.step(T_int, T_ext, 31536000.0);
}
```

### Module Coupling Points

```rust
#[test]
fn zone_balance_conserves_energy_with_all_sources() {
    // Solar + Conduction + Ventilation + HVAC
    let mut model = ThermalModel::from_spec(&spec);

    let solar_gain = 500.0;  // W
    let conduction_flux = -200.0;  // W (heat loss)
    let ventilation_flux = -50.0;  // W
    let hvac_load = 0.0;  // Free-float

    model.set_solar_gains(&[solar_gain]);
    model.set_conduction_flux(&[conduction_flux]);
    model.set_ventilation_flux(&[ventilation_flux]);

    // Energy balance: sum should approach zero for steady-state
    let balance = solar_gain + conduction_flux + ventilation_flux;
    assert!(balance.abs() < 0.1);  // W
}
```

## Anti-Patterns to Avoid

### 1. Mocking Internal Logic

**Bad**: Mock the 5R1C solver internals
```rust
#[test]
fn test_with_mock_solver() {
    let mock_solver = MockFiveR1CSolver::new();
    mock_solver.expect_step().returning(|...| 100.0);
    // ...
}
```

**Good**: Test against analytical solutions or reference data
```rust
#[test]
fn five_r1c_steady_state_matches_fourier() {
    let q_expected = delta_t / wall_spec.total_r_value();
    let q_actual = solver.step(T_int, T_ext, 0.0);
    assert_relative_eq!(q_actual, q_expected, epsilon = 0.1);
}
```

### 2. Testing Through Side Effects Only

**Bad**: Check that a file was written without checking values
```rust
#[test]
fn writes_results() {
    run_simulation();
    assert!(Path::new("output.csv").exists());
    // No check of actual values!
}
```

**Good**: Validate the actual physics output
```rust
#[test]
fn annual_energy_matches_reference() {
    let result = run_simulation();
    assert_relative_eq!(
        result.annual_heating_kwh, 1450.0,
        epsilon = 0.01,
        max_relative = 0.15  // ASHRAE 140 tolerance
    );
}
```

### 3. Brittle String Comparisons

**Bad**: Compare full error messages
```rust
#[test]
fn error_message() {
    let result = do_something();
    assert_eq!(result.unwrap_err().to_string(),
        "Invalid parameter: window_u_value must be between 0.1 and 5.0");
}
```

**Good**: Check error kind or use pattern matching
```rust
#[test]
fn invalid_parameter_returns_error() {
    let result = do_something();
    assert!(result.is_err());
    assert!(matches!(result.unwrap_err(), Error::InvalidParameter(_)));
}
```

### 4. Tests with No Assertions

**Bad**: Print-only tests
```rust
#[test]
fn check_output() {
    let result = compute();
    println!("Result: {:?}", result);
    // No assertion!
}
```

**Good**: Explicit assertions with meaningful messages
```rust
#[test]
fn computed_energy_is_positive() {
    let result = compute();
    assert!(result >= 0.0, "Energy should be non-negative, got {} kWh", result);
}
```

### 5. Testing Private Implementation Details

**Bad**: Test internal state fields
```rust
#[test]
fn internal_state_updated() {
    let model = ThermalModel::new(1);
    model.step_physics(0, 10.0, 3600.0);
    // Accessing private field:
    assert_eq!(model.internal_state.temp_mass, 15.3);
}
```

**Good**: Test public trait outputs
```rust
#[test]
fn step_returns_hvac_load() {
    let model = ThermalModel::new(1);
    let load = model.step_physics(0, 10.0, 3600.0);
    assert!(load.is_finite());
}
```

## Test File Organization

### Isolation Tests (per module)
```
tests/
├── weather_isolation.rs          # Weather module alone
├── solar_isolation.rs            # Solar module alone
├── conduction_5r1c_isolation.rs # Conduction module alone
├── ventilation_isolation.rs      # Ventilation module alone
└── zone_balance_analytical.rs   # Zone balance with mocks
```

### Integration Tests (multi-module)
```
tests/
├── ashrae_140_case_900.rs       # Full physics stack
├── api_integration_tests.rs      # HTTP API
├── cli_integration.rs           # CLI
└── hvac_bestest_validation.rs   # HVAC subsystem
```

## Running Tests

```bash
# All tests
cargo test --all

# One test file
cargo test --test solar_isolation

# One test
cargo test solar_altitude_40N_summer_solstice

# With output (for debugging)
cargo test -- --nocapture

# Integration tests only
cargo test --test '*integration*'

# Isolation tests only
cargo test --test '*isolation*'
```

## Performance Notes

- Isolation tests should run in <500ms
- Use `#[ignore]` for slow tests (full-year simulations)
- Profile with `cargo bench` for microbenchmarks
- Concurrency tests need `LOOM=1 cargo test --features loom` (30 min runtime)
